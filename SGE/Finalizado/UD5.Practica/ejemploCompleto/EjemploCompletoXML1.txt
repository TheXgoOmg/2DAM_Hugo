● En este ejemplo se construye la estructura visual para mostrar el modelo prueba.student en el backend de Odoo.
● Primero se define una vista de tipo lista (tree) en el modelo ir.ui.view.
	○ Esta vista muestra los campos name y topics, organizados en formato de tabla.
	○ Su función es puramente visual: no guarda datos, solo determina cómo se presentan los registros.
● A continuación, se crea una acción de ventana (ir.actions.act_window) llamada student_action_window.
	○ Esta acción enlaza el modelo prueba.student con sus vistas y define los modos de visualización: tree (lista) y form (formulario).
	○ Permite que el usuario vea la lista de estudiantes y, al hacer clic en un registro, abra el formulario para consultarlo o editarlo.
● Luego se construye un menú jerárquico en ir.ui.menu con tres niveles:
	○ Menú raíz: “Prueba”.
	○ Submenú: “Administración”.
	○ Elemento final: “Estudiantes”, que ejecuta la acción student_action_window.
● El recorrido del usuario sería: Prueba → Administración → Estudiantes.
	○ Al seleccionar “Estudiantes”, se abre la vista de lista con todos los registros del modelo prueba.student.
	○ Al hacer clic sobre un estudiante, Odoo abre su vista de formulario.
● Este flujo demuestra cómo vistas, acciones y menús trabajan juntos
	○ La vista define cómo se muestran los datos.
	○ La acción conecta la vista con el modelo.
	○ El menú permite acceder a esa acción desde la interfaz.
● Odoo puede generar vistas automáticas si solo se define la acción, pero son básicas y poco personalizables.
● Por eso, definir las vistas manualmente en XML, como en este ejemplo, brinda mayor control sobre el diseño, la disposición de campos y la experiencia del usuario.
